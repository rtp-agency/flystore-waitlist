# FlyStore, лист ожидания

Рекламная страница на один экран действия: человек читает, оставляет имя и контакт,
заявка падает нам в Telegram. Всё.

Проект самостоятельный. Ни базы, ни Redis, ни бота, ни control plane: страница это
статика, а единственный запрос к серверу делает форма. Папку можно унести куда угодно
и завести под неё отдельный репозиторий, зависимостей от основного проекта нет.

## Быстро

```bash
npm install
cp .env.example .env      # вписать токен бота и id чата
npm run local             # http://localhost:4321, заявки уходят по-настоящему
```

`npm run local` собирает страницу и поднимает маленький сервер, который отдаёт
статику и обрабатывает `/api/join` тем же кодом, что и боевые функции. Нужен он
ровно для одного: убедиться до выкладки, что заявка правда доезжает в чат.

## Что настроить

| Переменная | Где | Зачем |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | сервер | Токен от [@BotFather](https://t.me/BotFather). В браузер не попадает никогда. |
| `TELEGRAM_CHAT_IDS` | сервер | Куда падают заявки. Числовые id через запятую. |
| `ALLOWED_ORIGIN` | сервер | Необязательно. Адрес сайта, с которого принимаем форму. |
| `PUBLIC_TG_LINK` | сборка | Необязательно. Ссылка на наш телеграм в футере и после отправки. |

Свой id можно спросить у [@userinfobot](https://t.me/userinfobot), id группы приходит
с минусом. Бот должен уметь вам написать: для личного чата это значит, что вы один раз
нажали в нём «Старт», иначе Telegram молча откажет в доставке. В группе бот должен
состоять участником.

`ALLOWED_ORIGIN` заполняем после того, как страница встала на домен: пустая настройка
означает, что заявку нам в чат может слать кто угодно с любого сайта.

## Выкладка

Страница это чистая статика, а функция приёма заявки написана дважды, под два
хостинга. Лежат обе одновременно намеренно: хостинг видит свою и не замечает чужую,
переезд не требует правок в коде.

**Cloudflare Pages** (`functions/api/join.ts`)

* Build command: `npm run build`, output directory: `dist`, root directory: `waitlist`
  (если репозиторий общий с основным проектом).
* Переменные из таблицы выше: Settings, Environment variables. Токен пометить как
  secret.
* Папку `functions` Pages подхватывает сам, настраивать нечего.

**Vercel** (`api/join.ts`)

* Framework preset Astro, остальное по умолчанию.
* Переменные там же, Settings, Environment variables.
* Папку `api` Vercel подхватывает сам.

**Свой сервер**

```bash
npm ci && npm run build
node --env-file=.env scripts/serve.mjs      # за nginx, порт в PORT
```

## Как приходит заявка

```
Заявка в лист ожидания

Имя: Коля
Telegram: @kolya_dev
Почта: kolya@example.com
Источник: /?utm_source=tg&utm_campaign=avtumn
```

Под сообщением кнопка «Написать @kolya_dev»: ответить можно, не выходя из чата.
Источник это адрес страницы с utm-метками как есть, по нему видно, какое объявление
сработало.

Заявки нигде не хранятся, кроме вашего чата. Это осознанно: базы у страницы нет,
а сообщение в Telegram не теряется. Если однажды понадобится список, самое дешёвое
это дублировать заявку в Google-таблицу тем же запросом из функции.

Если доставка не удалась вообще никому, заявка целиком уходит в журнал хостинга
строкой `заявка не доставлена никому: {...}`, а человек видит «попробуйте ещё раз».
Достать её оттуда руками неприятно, но это лучше, чем потерять. Смотреть в Vercel:
проект, Logs.

## Защита

Маршрут открыт всему интернету, поэтому:

* скрытое поле-приманка, которое видит только робот;
* отсев отправки быстрее полутора секунд от загрузки страницы;
* `ALLOWED_ORIGIN`, если он задан.

Робот получает такой же вежливый ответ, как человек, и ничего не отправляется:
явный отказ он прочитает и подберёт обход.

npm test     # проверки разбора заявки, Node 24 читает TypeScript сам
